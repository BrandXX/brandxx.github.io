# defiantly_not_regex static subsite

This folder publishes directly to:

`https://techsoftsys.com/defiantly_not_regex/`

## Where to upload resources

- Main image: `defiantly_not_regex_b64_ocrsafe_3000.png`
- Shared page styles: `style.css`
- Rendered HTML pages: `pages/`

Source `.docx` files are intentionally kept outside the public web root:

`source-docs/defiantly_not_regex/`

## Page pattern

The main page is:

- `index.html`

Each uploaded doc should get a matching static HTML page in `pages/`, for example:

- `pages/thesis.html`
- `pages/backstory.html`
- `pages/whitepaper.html`

Then add links to those pages in the `index.html` navigation.

## Editorial maintenance

The HTML pages are the maintained web copy. The original `.docx` files remain
in `source-docs/defiantly_not_regex/` as historical source material; they are
not regenerated by the site build.

Keep the thesis concise, the backstory personal, and the white paper focused
on extraction, interpretation, verification, and recovery. Lead with the
principle and its human stakes; use PIPER as supporting experience rather
than turning these pages into a project history. Preserve the origin in the author's AI lab:
the original Hermes/Open-WebUI PIPER intent architecture led to the human
communication analogy and the visual artifact, not the other way around.
Distinguish the historical gateway, filter experiments, current early plugin,
and future direction. Do not project today's advisory-plugin limits backward
onto earlier implementations, or present historical/planned capabilities as
current-plugin features. Keep technical qualifications proportionate to the
argument, and distinguish preserving intent from exact byte recovery.
The white paper's context payload and Base64 must match the rebuilt PNG's
`AI_CONTEXT` and `AI_CONTEXT_B64` metadata, including UTF-8 punctuation.
